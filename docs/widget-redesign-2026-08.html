ConPaws Widget Redesign

Mockups and a buildable spec for the iOS Home Screen widgets. The shipped widgets show at most one upcoming event in system colors. This redesign adds a systemLarge day view, puts the brand color to work in every family, gives systemMedium real rows, and — per the 2026-08-28 scope call — covers the Lock Screen accessory families and the watch Smart Stack complication in the same build, on snapshot schema v2. Swift implementation comes later, as its own phase.

Scope. This page specifies presentation only. The first build targets snapshot schema v2: everything in today's WidgetConventionSnapshot / WidgetEventSnapshot plus one new field, ageRating on events (§6). The module's version gate already handles v1/v2 mismatches safely — an old watch build reading a v2 payload keeps working because unknown fields decode as absent.

Contrast flag: #00729C on white measures ≈4.7:1 — fine at headline sizes, below the app's AAA bar for small text. That is why BrandSmallText exists: use it for any brand-colored run below ~13 pt in light mode, and document the divergence from the app's AAA policy in the asset catalog comment. Dark mode's #18B7F2 on #1C1C1E clears 8:1 and needs no variant.

Typography is all system text styles (SF): eyebrow caption2 bold, event titles footnote semibold, countdown numerals title2 rounded bold monospacedDigit, times caption2 semibold monospacedDigit.

The mark, not the icon — and no emoji. Apple's widget guidance warns against dropping your app icon into a widget, and the concern is real: the system already names the app, and a full-color icon turns to mud under iOS 18 tinted rendering. ConPaws still carries its brand here, deliberately: a small monochrome compass-paw mark sits before the convention name in every header, and a larger one anchors the empty and "all done" states. It ships as a template-rendered vector asset (ConPawsMark) in the widget target, so accented, tinted, and vibrant modes recolor it exactly like the text beside it — brand presence without the full-color icon Apple is warning about. Emoji stay banned for the same mechanical reason: they render as color bitmaps that ignore rendering modes and glare on a tinted Home Screen. The only other glyph is figure.walk on the leave strip.

2 · systemSmall — refined

One next event, brand-tinted time, room line. The empty state swaps the old generic calendar glyph for the ConPaws mark.

Leave window: when now is inside startAtMs − reminderMinutes·60000 … startAtMs for the next event, the small widget swaps its Next layout for the countdown above — the minutes figure is the hero, in title2 rounded bold monospacedDigit.

3 · systemMedium — richer

Current event plus the next two, room at equal weight with the title. In the leave window the bottom row is replaced by the leave strip — the redesign keeps that state first-class, not an afterthought.

4 · systemLarge — the day view (new)

The highest-value piece per the earlier specimen doc. Grammar borrowed from the day views people already read — Apple Calendar and Fantastical large widgets: date header, a time rail of stacked rows, the running event raised on a brand chip, and an overflow count instead of clipped rows.

5 · Rendering-mode rules

  • Accented/tinted: mark the time column, rails, and the now-chip widgetAccentable(). Hierarchy must survive recoloring — it is carried by weight and size, never by hue alone (the tinted specimens above are the test).
  • Vibrant (Lock Screen families): unchanged from shipped; accessory families keep their current layouts.
  • Symbols: two glyphs only — the ConPawsMark template vector and SF Symbol figure.walk — both template-rendered and sized with the text style beside them, so accented/tinted/vibrant modes recolor them with the text. No emoji anywhere in a widget.
  • StandBy: container background stays systemBackground via containerBackground(for: .widget); no full-bleed art.

6 · Buildable spec (schema v2)

FamilyRowsSelection ruleFields used
systemSmall1 First event with endAtMs > now (current preferred over next) title, startAtMs, room ?? location
systemMedium≤3 Current event (if any) + next two by startAtMs + endAtMs for the Now chip
systemLarge≤5 + overflow Events whose day (in timeZoneIdentifier) is today; drop finished ones; count the remainder into "+N more today" + conventions[].dateRangeLabel, name
  • Leave window (all families): active when the next event has reminderMinutes ≠ null and now ≥ startAtMs − reminderMinutes·60000 and now < startAtMs. Small swaps to the countdown layout; medium and large pin the leave strip above the rows (large keeps the day list beneath it, dropping one row to make room). The strip and its countdown are widgetAccentable(). Timeline entries are pre-built at the window's open and close instants — the shipped provider's change-point mechanism already does this and carries over unchanged.
  • "Today" is computed in the convention's timeZoneIdentifier, never the device zone — same rule the app and watch already follow.
  • Pre-con: reuse the shipped countdown classifier (ConPawsCountdown) for the large countdown state; footer shows the starred-event count.
  • Empty and "all done" states both name the next actionable thing when one exists (first event tomorrow), else the star hint.
  • Truncation: titles 1 line all families except large's now-chip (2 lines); rooms always 1 line.
  • VoiceOver: one element per row — "7:00 PM, Costume Crafting 101, Game Hall"; the now-chip prepends "Now, ends 1:00 AM".
  • Deep links: unchanged — every family opens conpaws://schedule?conventionId=….
  • Age pill (schema v2): ageRating (string, absent = all-ages) rides on WidgetEventSnapshot. Medium and large rows render it as the same pill the app uses ("13+ Teen", "18+"); small and the accessory families skip it — no room at those sizes.
  • Which convention (decided 2026-08-28: both): by default every widget picks automatically — active convention first, else the nearest upcoming one, the same rule the watch follows. Long-press → Edit Widget adds an optional per-widget pin via an AppIntent configuration (ConventionEntity query over the snapshot). A pinned convention that later disappears falls back to automatic instead of rendering an error.
