## Infrastructure ownership

- **Infrastructure (`packages/infra`):** **Alchemy** (`alchemy.run.ts`) owns production — the waitlist and catalog D1 databases, the `conpaws-cdn` R2 bucket on cdn.conpaws.com, the site, API (api.conpaws.com) and hourly waitlist reconciler Workers, their bindings and secrets, and migrations. The same deploy puts the admin console on admin.conpaws.com with first-verified-signup owner setup, then invite-only email-code sign-in and no Cloudflare Access: it derives the code key from `ALCHEMY_PASSWORD` (so the key stays stable across deploys) and binds Cloudflare Email Service (`EmailSender`, from `no-reply@conpaws.com`) and a `RateLimit`. conpaws.com must be onboarded for Email Sending once in the dashboard, and the first owner signs up at `/sign-in` with an emailed code. Setup is claimed atomically and stays closed after membership deletion; the laptop `admin:invite` command remains available for owner recovery. `bun run deploy` / `bun run destroy` run only in GitHub Actions on `main` (see *Deploy rule* below). `apps/web/wrangler.jsonc` is **local dev and CI preview only**; never put a real `database_id` in it. Use the installed Alchemy version from `packages/infra/package.json`. Cloudflare credentials are optional for local validation and required to deploy. Alchemy does not do canary or automatic rollback — manual rollback uses workflow_dispatch on `.github/workflows/deploy-web.yml` with a last-good SHA (an ancestor of `origin/main`). Deploy env validation includes `NEXT_PUBLIC_SITE_URL` and the Turnstile site key. See the **Prerelease Site** page in Notion (§Deployment).
